# ロードマップ（段階的に進める）

各サイクルは docs/CYCLE.md の手順で 1 項目ずつ進める。完了したら [x] にしてコミット。

## Stage 1: MVP
- [x] ワンタップ記録 / おすすめ / ヒートマップ / 路線管理 / PWA

## Stage 2: 手放せなくする
- [x] 記録の取り消し・履歴一覧（誤タップ対策）
- [x] JSON エクスポート/インポート（機種変更対策）
- [x] 「いつもの時刻」比較: おすすめ枠が普段より何ポイント空いているか表示

## Stage 3: 通勤の「ついで」メモ
- [x] 乗換に便利な号車・ドア位置メモ（路線×駅ごと）
- [x] 記録リマインド通知（いつもの時刻に「今日の混み具合は？」）→ PWA単体は定時通知不可のため、平日繰り返しの .ics をカレンダーに追加する方式

## Stage 4: 公開
- [ ] 静的ホスティングへ公開（※外部公開はユーザー確認後。公開URL確定後に og:image(PNG・絶対URL) を追加）
- [x] OGP・使い方（ページ内の使い方＋よくある質問）

## Stage 5: 続けたくなる（dashboard ブレスト 2026-10-01 より）
- [x] 平日ストリーク「連続N日」＋直近7日のドット（土日は途切れない扱い）
- [x] 今の時間帯の混雑予想を記録ボタンの上に表示（データ不足時は「あと N 回で予想」）
- [x] 路線の自動選択（開いた時刻の枠で最も記録している路線を初期選択）

## Stage 6: 記録の精度（dashboard ブレスト 2026-10-01 より）
- [x] コード見直し（10 サイクル分の重複・不整合を整理）
- [x] 状況タグ「遅延」「雨」を記録時にトグルで付ける。おすすめ・予想は平常時の記録だけで計算
- [x] おすすめ・予想は直近 90 日の記録だけを使う（季節・ダイヤ改正で古いデータがずれるため）

## Stage 7: 公開前の品質（dashboard ブレスト 2026-10-01 より）
- [x] Service Worker を network-first（オフライン時だけキャッシュ）にし、更新が利用者に確実に届くようにする
- [x] 混雑色の白文字コントラストを 4.5:1 以上に（WCAG AA。黄・黄緑が約 3:1 で不足）
- [x] データ保全: storage.persist() を要求し、最後の書き出しから 30 日超で書き出しを促す

## 不採用メモ
- 降車アラーム: PWA は画面ロックで位置情報停止
- 天気の自動取得（ブレスト案）: 位置情報＋外部API通信が必要で「端末内のみ」に反する → 手動の「雨」タグで代替
- 号車別の混雑記録: 入力負担が増える。乗換メモで代替し需要を見て再検討
- 数千件時の仮想スクロール（ブレスト案）: 履歴は10件表示・集計はO(n)で実害なし
- 取消トースト強化（ブレスト案）: Stage 2 で実装済み
- 混雑の全ユーザー共有: サーバ・個人情報・荒らし対策が必要。Stage 4 以降に需要を見て判断
